# opencode-benchmark

**What is this?** A daily-updated answer to one question: *which OpenCode Go tariff gets you
the most intelligence for your money?*

OpenCode Go prices hide the real cost behind quota multipliers and context splits — a tariff
named "Flash" can cost four times what its "Max" sibling does for reasons nothing on the price
list explains. This tool decodes it: for every tariff it shows what one typical session cost,
how many **millipercents of your monthly quota** it eats, and how the model's benchmark score
compares to what you pay.

**Web version:** <https://krivich.github.io/opencode-benchmark/> — live table, default-sorted
by best score-per-mp; every column is sortable (click a header).
**Data (JSON):** [`docs/report.json`](docs/report.json) — the same report, machine-readable,
with a documented schema: [`docs/report.schema.json`](docs/report.schema.json). Daily snapshots
with change diffs land in [`docs/history/`](docs/history/) — the report doubles as a time series.

## How it works

- **Fetch.** Downloads the Go price table and the latest monthly benchmark from the index page.
- **Match.** Fuzzy model-name matching (Levenshtein) with strict guards:
  - Versions `X.Y` are protected: `2.5` ≠ `2.6` (parameter sizes like `27B` and build dates
    like `0731` do not count as versions).
  - Subtype tokens are hard filters: `max`, `pro`, `flash`, `plus`, `lite`, `mini`, `nano`,
    `ultra`, `turbo`, `vision`, `code`, `instruct`, `preview`, `thinking`, `omni`. If the marker
    is in one name but not the other, they are different models.
  - Similarity `< 0.50` counts as "not found" — unless one name is an exact substring of the
    other (`Hy3` inside `Tencent Hy3` is a real match, `✓`).
  - `≥ 0.85` → confident `✓`; `0.55–0.85` → plausible `⚠`; `0.50–0.55` → weak `—`.
  - If several tariffs claim the same benchmark row, the most confident wins, the rest
    honestly stay "not in benchmark".
- **Sanity check.** The parsed tables must look like the benchmark (enough rows, numeric
  scores, Cost/Speed present). Otherwise the run fails cleanly and the previous page is kept —
  no garbage-in / garbage-out writes.
- **Compute.** A typical session = **155K context, 95% cache-read, ~300 output tokens**:

  ```
  input      =  5% × 155_000 =   7_750
  cache_read = 95% × 155_000 = 147_250
  output     =              =     300
  ```

  `$/session = (input × $/1M + cache_read × $/1M + output × $/1M) / 1 000 000`
  `mp/session = $/session ÷ quota($) × 100 000` (quota multiplier = 60 ÷ quota).

## Local run

```bash
npm ci
npm start
```

The script fetches current data, regenerates everything we publish, and a scheduled GitHub Action
(`update-pages.yml`, daily 06:00 UTC) does the same automatically.
